პირველ რიგში, გავმართეთ გარემო და დავაკვირდით მოცემულ ფაილებს:

* **`loan_month_recovery.csv` - ანუ სესხები:** 70,173 ჩანაწერი სესხების დონეზე (ამოღების 24-თვიანი ისტორიით).
* **`Features.csv` - მახასიათებლები:** 29,763 ჩანაწერი კლიენტების ფინანსური და საკრედიტო ისტორიით.
* **`feature_dictionary.csv`:** 50 ცვლადის განმარტება.

თავდაპირველად მოვამზდეთ მონაცემები.  
გავასწორეთ იდენტიფიკატორის სახელი - 'client_key' -> 'CLIENT_KEY', იმისათვის, რომ კლიენტის მონაცემები და სესხების ბაზა ერთმანეთს უფრო მარტივად და უშეცდომოდ დავუკავშიროთ.  
შევქმენით feat_map (ლექსიკონი, რომელშიც ცვლადის ტექნიკურ სახელს შეესაბამება მისი რეალური განმარტება), რათა მომავალში ანალიზისას უფრო იოლად გავიგოთ მათი შინაარსი და ძიება არ დაგვჭირდეს, მაგალითად, გრაფიკების გამოყენების დროს.

შემდეგ დავიწყეთ ამ მონაცემების დამუშავება.  
მონაცემების დასამუშავებლად ჯერ შევქმენით M_cols, რომელშიც მოვაგროვეთ 24-ვე თვის გადახდის სვეტის სახელი (M01_PAID-დან M24_PAID-მდე). ასე ყველა საჭირო თვის მონაცემზე ოპერაციები ერთდროულად შეგვიძლია, ჩავატაროთ.  
შემდეგ გადავამოწმეთ რამდენად სუფთაა ჩვენი დათაბაზა, assert-ების საშუალებით. დავრწმუნდით, რომ features-ში არ გვხვდება კლიენტები განმეორებით, სესხების აიდები უნიკალურია, გადახდებში უარყოფითი მონაცემები არაა, ასევე შევსებული თვეების რაოდენობა ემთხვევა ჩვენი დაკვირვების 24-თვიან პერიოდს.
